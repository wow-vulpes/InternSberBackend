# Контроль качества данных по целям сотрудников

Проект backend-сервиса для проверки целей и ключевых результатов, хранения истории прогонов, расчёта метрик и выдачи результатов через REST API. Разработка ведётся поэтапно с ИИ-ассистентом.

**Текущее состояние:** каркас Spring Boot, тест загрузки контекста и проверки Java/форматирования. Правила, PostgreSQL, миграции, демоданные, бизнес-API и Docker Compose пока не реализованы. Frontend исключён из согласованного объёма.

## Сборка каркаса

Нужны JDK 21 и доступ к Maven Central при первом использовании Maven, зависимостей или новых плагинов. В Linux/macOS Wrapper скачивает Maven через wget либо curl; для распаковки использует unzip или tar при отсутствии unzip. Отдельная установка Maven не нужна: Wrapper использует Maven 3.9.11. JAVA_HOME должен указывать на каталог установленного JDK 21, а не на java или bin.

Из корня проекта:

```sh
cd backend
./mvnw --version
./mvnw -B compile
```

На Windows используйте `.\mvnw.cmd` в PowerShell или `mvnw.cmd` в cmd вместо `./mvnw`. Windows-запуск пока не проверен.

При compile/test/verify автоматически проверяются JDK 21 и формат всех Java-исходников. При неверной версии Java сборка завершается с подсказкой настроить JAVA_HOME. Команда `--version` только показывает окружение и не выполняет эти проверки.

## Тесты и форматирование

Из backend/:

```sh
./mvnw -B test
./mvnw spotless:check
```

Сейчас есть один тест KkdApplicationTest.contextLoads: загрузка Spring-контекста без БД и без запуска HTTP-сервера. Бизнес-тестов пока нет.

Формат Java — Google Java Format 1.28.0, стиль AOSP (отступ 4 пробела). Для исправления форматирования используйте `./mvnw spotless:apply`. Обычная сборка только проверяет формат и не изменяет файлы.

Полная проверка сборки — `./mvnw -B verify`: она также запускает тесты и создаёт исполняемый JAR в backend/target/. Команда проверена на текущем каркасе. Результаты фиксируются в docs/progress.md.

## Локальный запуск

Из backend/:

```sh
./mvnw spring-boot:run
```

По умолчанию порт 8080. Для другого порта:

```sh
SERVER_PORT=8081 ./mvnw spring-boot:run
```

Пример выше предназначен для Linux/macOS. В PowerShell сначала задайте `$env:SERVER_PORT = "8081"`, затем выполните `.\mvnw.cmd spring-boot:run`. Для остановки используйте Ctrl+C. Порт должен быть свободен.

Это команда запуска пустого приложения: бизнес-маршруты отсутствуют, стандартный ответ 404 ожидаем. Отдельный запуск HTTP-сервера проверен в Linux с SERVER_PORT=8081; GET /api/runs возвращает 404.

После успешной verify можно запустить собранный JAR без Maven. Из backend/ в Linux/macOS:

```sh
"$JAVA_HOME/bin/java" -jar target/kkd-service-0.0.1-SNAPSHOT.jar
```

Если SERVER_PORT не задан, используется порт 8080. Запуск JAR на этом порту также проверен.

`.env.example` содержит пример переменной SERVER_PORT со значением 8080. Spring Boot и Maven Wrapper не загружают .env автоматически: простого копирования примера в .env для локального запуска недостаточно. Задайте переменную в окружении, как показано выше. Пароли БД на текущем этапе не требуются.

## Что уже проверено

- Maven Wrapper: Maven 3.9.11 и JDK 21 в Linux.
- Компиляция и тест загрузки контекста: 1 тест, без ошибок и пропусков.
- Проверки формата Java и отклонение JDK 18 при сборке.
- Команды spotless:check и spotless:apply на текущих исходниках.
- Полный цикл verify, создание исполняемого JAR и запуск JAR на порту 8080.
- Запуск через spring-boot:run с SERVER_PORT=8081; проверочные процессы остановлены.

Это проверки каркаса, а не готового ККД. Запуск по инструкции в чистом окружении и на Windows ещё не проверен.

## Что появится дальше

Четыре правила: GOAL_NO_OWNER, GOAL_NO_KR, KR_WEIGHTS_SUM, KR_STALE_PROGRESS. Отдельный Java-компонент получает данные и возвращает проблемы; SQL хранит данные и результаты. Метрики и дельта рассчитываются на сервере по неизменяемым снимкам.

Команды Docker Compose, проверки миграций накат → откат → повторный накат и примеры API будут добавлены вместе с рабочей реализацией. Пока их нет, соответствующие критерии не выполнены.

Доступ к Storybook, существующим корпоративным сервисам и ИФТ не предоставлен. Локальные проверки не подтверждают корпоративную интеграцию или развёртывание на ИФТ.
