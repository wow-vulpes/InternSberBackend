# Контроль качества данных по целям сотрудников

Проект backend-сервиса для проверки целей и ключевых результатов, хранения истории прогонов, расчёта метрик и выдачи результатов через REST API. Разработка ведётся поэтапно с ИИ-ассистентом.

**Текущее состояние:** каркас Spring Boot, проверки Java/форматирования, доменные модели, валидация входа и четыре правила ККД. DataQualityChecker.check получает цели и дату снимка и возвращает неизменяемый список проблем в стабильном порядке. PostgreSQL, миграций, демоданных, бизнес-API и Docker Compose пока нет. Frontend исключён из согласованного объёма.

## Сборка каркаса

Нужны JDK 21 и доступ к Maven Central при первом использовании Maven, зависимостей или новых плагинов. В Linux/macOS Wrapper скачивает Maven через wget либо curl; для распаковки использует unzip или tar при отсутствии unzip. Отдельная установка Maven не нужна: Wrapper использует Maven 3.9.11. JAVA_HOME должен указывать на каталог установленного JDK 21, а не на java или bin.

Из корня проекта:

```sh
cd backend
./mvnw --version
./mvnw -B compile
```

На Windows используйте `.\mvnw.cmd` в PowerShell или `mvnw.cmd` в cmd вместо `./mvnw`. Windows-запуск пока не проверен.

При compile/test/verify автоматически проверяются JDK 21 и формат всех Java-исходников. При неверной версии Java сборка завершается с подсказкой настроить JAVA_HOME. Команда `--version` только показывает окружение и не выполняет эти проверки.

## Тесты и форматирование

Из backend/:

```sh
./mvnw -B test
./mvnw spotless:check
```

KkdApplicationTest.contextLoads проверяет загрузку Spring-контекста без БД и без запуска HTTP-сервера. GoalSnapshotTest, KeyResultSnapshotTest, IssueTest и DataQualityCheckerTest проверяют контракты моделей, валидацию входа и идентичность объектов.

DataQualityRulesTest проверяет все четыре правила, границы 45 дней, точную сумму весов, пропуск неактивных целей, совместные нарушения, стабильный порядок, неизменяемость и повторяемость результата. Временные проверки недоступности расчёта удалены и заменены проверками найденных проблем.

Формат Java — Google Java Format 1.28.0, стиль AOSP (отступ 4 пробела). Для исправления форматирования используйте `./mvnw spotless:apply`. Обычная сборка только проверяет формат и не изменяет файлы.

Полная проверка сборки — `./mvnw -B verify`: она также запускает тесты и создаёт исполняемый JAR в backend/target/. На итоговой проверке шага 2 полный цикл прошёл: 100 сценариев, без ошибок и пропусков. Результаты фиксируются в docs/progress.md.

## Локальный запуск

Из backend/:

```sh
./mvnw spring-boot:run
```

По умолчанию порт 8080. Для другого порта:

```sh
SERVER_PORT=8081 ./mvnw spring-boot:run
```

Пример выше предназначен для Linux/macOS. В PowerShell сначала задайте `$env:SERVER_PORT = "8081"`, затем выполните `.\mvnw.cmd spring-boot:run`. Для остановки используйте Ctrl+C. Порт должен быть свободен.

Это команда запуска пустого приложения: бизнес-маршруты отсутствуют, стандартный ответ 404 ожидаем. Отдельный запуск HTTP-сервера проверен в Linux с SERVER_PORT=8081; GET /api/runs возвращает 404.

После успешной verify можно запустить собранный JAR без Maven. Из backend/ в Linux/macOS:

```sh
"$JAVA_HOME/bin/java" -jar target/kkd-service-0.0.1-SNAPSHOT.jar
```

Если SERVER_PORT не задан, используется порт 8080. Запуск JAR на этом порту также проверен.

`.env.example` содержит пример переменной SERVER_PORT со значением 8080. Spring Boot и Maven Wrapper не загружают .env автоматически: простого копирования примера в .env для локального запуска недостаточно. Задайте переменную в окружении, как показано выше. Пароли БД на текущем этапе не требуются.

## Реализованные правила

Все правила работают только для активных целей и их КР.

| Код | Условие | Важность |
| --- | --- | --- |
| GOAL_NO_OWNER | Нет ответственного: null, пустая или пробельная строка | critical |
| GOAL_NO_KR | Нет ни одного КР | critical |
| KR_WEIGHTS_SUM | КР есть, сумма весов численно отличается от 100 | major |
| KR_STALE_PROGRESS | Нет даты обновления факта либо прошло больше 45 календарных дней до даты снимка | minor |

Цель без КР не получает дополнительную проблему суммы весов. Ровно 45 дней допустимо; будущая дата не устаревшая. Вес считается через BigDecimal без округления; диапазон отдельного веса выбранными правилами не проверяется. Проблема КР содержит ID связанной цели и подразделения.

DataQualityChecker — обычный Java-компонент без Spring, SQL и обращения к системным часам. Некорректный вход отклоняется до выполнения правил через IllegalArgumentException, без частичного результата. Проверка иерархии и агрегация по дочерним подразделениям появятся на следующих шагах.
