# Состояние реализации и проверки

Дата общей проверки: 31 октября 2026. Проверены доменные правила, схема хранения PostgreSQL, выполнение прогонов, демонстрационные данные, метрики, сравнение снимков, REST API и контейнерное развёртывание.

## Реализовано

- Spring Boot на Java 21, Maven Wrapper, проверки версии Java и форматирования.
- Четыре доменных правила ККД, валидация входа и неизменяемый результат в стабильном порядке.
- PostgreSQL 17.11: девять таблиц, составные связи снимков, справочник правил, защита истории, проверка циклов, функция потомков и VIEW статистики.
- Liquibase 4.31.1: четыре SQL-миграции с обратными скриптами, baseline-тег, единая служебная история в public для Spring, Maven и тестов.
- Java-сценарий прогонов: согласованный снимок, расчёт реальными правилами, сохранение проблем, выбор предыдущего успешного прогона.
- Savepoint для отката частичных результатов и сохранения FAILED; сериализация обычных прогонов и демо общей блокировкой.
- Демо: 24 цели, 3 подразделения и 2 прогона, атомарная инициализация, повторный/параллельный старт без дублей.
- Отдельные команды запуска прогонов и демо; по умолчанию выключены.
- Метрики: доля корректных целей, уникальные цели с проблемами, общее число проблем; дельта и полезное направление изменения, текущая важность.
- SummaryService: выборка текущего/прошлого подразделения с потомками в каждом снимке, счётчики важности и новых/сохраняющихся/исправленных проблем.
- REST API: список прогонов, сводка, список проблем с фильтрами/пагинацией; snake_case DTO, проверка параметров и единый формат ошибок.
- Полный Compose: приложение и PostgreSQL, ожидание готовности миграций/демо, конфигурация через окружение.
- Actuator health с readiness по состоянию приложения и БД; liveness без зависимости от БД.
- Многоэтапный Dockerfile, запуск без root с read-only root; GitHub Actions с verify и проверкой контейнерного развёртывания.

## Проверки REST API (шаг 6)

- Полный verify завершён с кодом 0: 253 сценария, без ошибок и пропусков. JAR собран. Зависимости и миграции не менялись.
- Проверены три GET endpoint-а, точный состав JSON и обязательные null, ISO-даты/время, регистр значений, глобальные счётчики и статусы в списке прогонов.
- Проверены все четыре правила и все три важности, фильтр по подразделению с потомками, комбинации фильтров, пустой результат, страницы без повторов, верхние границы limit/offset и total до пагинации.
- Неверные/пустые/отсутствующие/повторные/неизвестные параметры дают 422; неизвестные ресурсы — 404; RUNNING/FAILED не выдаются как готовые результаты. Значения ID передаются параметрами SQL. Исторические названия не меняются при редактировании источника и добавлении следующего прогона.
- 500 не раскрывает SQL, пароли, адрес БД или классы исключений. Серверная IllegalArgumentException не маскируется под ошибку пользовательского параметра.
- В отдельном проекте kkd-step6-check выполнено 15 настоящих HTTP-запросов к собранному JAR: список прогонов, обе сводки, список/фильтр/страница проблем, ошибки 404/405/406/422 и 500. Код 500 проверен обратимым переименованием VIEW только во временной БД; VIEW восстановлен и следующий GET /api/runs снова вернул 200.
- Временная БД после проверки содержала только 2 демопрогона и 5 записей Liquibase. Приложение остановлено; собственные контейнер, сеть и том kkd-step6-check удалены. Пользовательские БД не использовались, логи и временная конфигурация вне Git.
- README содержит команды curl, ограничения параметров, таблицу ошибок и ссылки на полный контракт в specs/design.md.

## Внешние ограничения и необязательные функции

- Удалённое выполнение GitHub Actions; workflow и его команды проверены локально.
- Запуск на Windows и в новой ОС без предварительного Docker-кэша не проверен; чистая копия исходников и новый том проверены на Linux.
- Корпоративная интеграция, Storybook, требования команды и ИФТ: материалы и доступ не предоставлены; frontend исключён из согласованного объёма.
- Необязательное расписание и авторизация не реализованы.

Команды воспроизведения — в [README](../README.md); покрытие требований — в [requirements.md](../specs/requirements.md).
