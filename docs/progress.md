# Состояние реализации и проверки

Дата проверки: 30 октября 2026. Проверены доменные правила, схема хранения PostgreSQL, выполнение прогонов, демонстрационные данные, метрики и сравнение снимков.

## Реализовано

- Spring Boot на Java 21, Maven Wrapper, проверки версии Java и форматирования.
- Четыре доменных правила ККД, валидация входа и неизменяемый результат в стабильном порядке.
- PostgreSQL 17.11: девять таблиц, составные связи снимков, справочник правил, защита истории, проверка циклов, функция потомков и VIEW статистики.
- Liquibase 4.31.1: четыре SQL-миграции с обратными скриптами, baseline-тег, единая служебная история в public для Spring, Maven и тестов.
- Java-сценарий прогонов: согласованный снимок, расчёт реальными правилами, сохранение проблем, выбор предыдущего успешного прогона.
- Savepoint для отката частичных результатов и сохранения FAILED; сериализация обычных прогонов и демо общей блокировкой.
- Демо: 24 цели, 3 подразделения и 2 прогона, атомарная инициализация, повторный/параллельный старт без дублей.
- Отдельные команды запуска прогонов и демо; по умолчанию выключены.
- Метрики: доля корректных целей, уникальные цели с проблемами, общее число проблем; дельта и полезное направление изменения, текущая важность.
- SummaryService: выборка текущего/прошлого подразделения с потомками в каждом снимке, счётчики важности и новых/сохраняющихся/исправленных проблем.
- Compose для PostgreSQL, конфигурация через окружение.

Итого: 183 автоматических сценария без ошибок и пропусков. MigrationLifecycleTest и RunServiceIntegrationTest используют пользователя kkd, чтобы проверить работу при совпадении имени пользователя и бизнес-схемы PostgreSQL.

После накатов отдельно проверены 9 бизнес-таблиц, 4 правила и 5 записей истории Liquibase. После отката бизнес-схема отсутствует, служебные таблицы остаются пустыми. Интеграционный тест сравнивает таблицы, колонки, ограничения, индексы, функции, триггеры и VIEW до и после отката.

Окружение: Linux, PostgreSQL 17.11, Testcontainers 1.21.4, Docker 29.9.1. Проверки использовали отдельные временные БД; приложение остановлено, временные контейнеры и том проверки удалены.

Демонабор содержит 3 новые, 5 сохраняющихся и 5 исправленных проблем во втором прогоне. Эти значения проверены как свойства данных и через готовый прикладной расчёт; HTTP API пока не подключён.

## Проверки метрик и сравнения (шаг 5)

- Полный verify завершён с кодом 0; JAR содержит QualityMetricsCalculator, SummaryService и SummaryRepository. Зависимости и миграции не менялись.
- На демо U1: доля 65.2 → 65.2, целей с проблемами 8 → 8, проблем 10 → 8, дельта проблем 3/5/5. Для U2 вместе с U3: доля 86.7 → 80.0, целей с проблемами 2 → 3, проблем 4 → 3, дельта 1/2/2.
- Проверены разность округлённых долей, HALF_UP на границе, нулевой знаменатель, отсутствие сравнения, сравнение с пустой областью, все направления изменений и важности.
- Проверены перенос подразделения и цели между ветвями, удаление и деактивация целей, появление нового подразделения, замена ID КР и сохранение идентичности при неизменном объекте.
- Изменение и удаление текущих источников, а также более поздний прогон не меняют ранее рассчитанную историческую сводку. RUNNING/FAILED и неизвестные ресурсы отклоняются явно.
- Важность метрик согласована как максимальная важность текущих проблем; без проблем null. HTTP-маршруты не добавлялись. Новая проверка отдельного HTTP-запуска JAR для шага 5 не выполнялась; Spring-связи проверены интеграционными тестами.
