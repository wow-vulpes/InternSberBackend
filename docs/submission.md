# Проверка решения перед сдачей

Реализован самостоятельный backend модуля ККД. Точка входа — [README](../README.md), требования — [specs/requirements.md](../specs/requirements.md), модель данных и API — [specs/design.md](../specs/design.md). Папка specs/ — выбранный артефакт работы с ИИ по условию задания.

## Маршрут проверки

1. Создайте .env из .env.example и выполните `docker compose up --build -d --wait` из корня. Нужен Docker с Compose v2; JDK на хосте не требуется. Сервис применит миграции и создаст два демопрогона. Повторный запуск не дублирует демо.
2. Откройте `GET http://localhost:8080/api/runs`: ожидаются demo-2026-10-26 и demo-2026-10-19 со статусом completed и 8/10 проблемами. Даты демо фиксированы и не зависят от дня запуска.
3. Запросите `GET /api/kkd/summary?run_id=demo-2026-10-26&unit_id=U1`: доля корректных целей 65.2%, целей с проблемами 8, проблем 8; сравнение с первым прогоном, дельта проблем new/persisting/resolved = 3/5/5. Метрики имеют key/unit/value и trend=better/worse/unchanged. Массив issues_by_severity содержит current/previous/delta: critical 3/5/−2, major 2/2/0, minor 3/3/0.
4. Запросите `GET /api/kkd/issues?run_id=demo-2026-10-26&unit_id=U2&rule=KR_STALE_PROGRESS&severity=minor&limit=1&offset=1`: total=2, один объект KR11. unit_id включает потомков из снимка. Для limit=201 ожидается 422 INVALID_PARAMETER, для неизвестного run_id — 404 RUN_NOT_FOUND.
5. Проверьте `GET /actuator/health/readiness`: 200 UP после полного старта, без деталей подключения. Приложение в контейнере работает без root.
6. `docker compose down` сохраняет том. Следующий `docker compose up -d --wait` возвращает ту же историю. Для нового прогона выполните контейнерную команду из раздела README «Демо и выполнение прогонов».

Примеры curl, команды тестов и порядок отката находятся в README. Полный `./mvnw -B verify` из backend/ требует JDK 21 и Docker; пройдено 259 сценариев без ошибок и пропусков. Проверка `python3 scripts/check_compose.py` использует отдельный проект, сама проверяет восстановление БД и удаляет только собственные ресурсы.

## Результаты и принятые решения

| Область | Реализация и доказательство |
| --- | --- |
| Правила | Четыре правила в DataQualityChecker; только активные цели, точный BigDecimal, границы 45/46 дней покрыты тестами |
| Метрики | Три метрики, текущие/прошлые значения, дельта, тренд и важность; отдельные доменные и PostgreSQL-тесты |
| История | Снимки источников и иерархии на каждый прогон; изменение текущих данных не меняет завершённые результаты |
| БД | Девять таблиц, рекурсивная функция потомков, проверка циклов, VIEW статистики, ограничения и защита истории |
| Миграции | Liquibase с явными rollback; накат → откат → повторный накат проверены на PostgreSQL 17.11 |
| API | Три GET endpoint-а, фильтры, limit/offset/total, стабильный порядок и единая оболочка ошибок |
| Демо | 24 цели, 3 подразделения, два прогона реальными правилами; все важности и категории изменений |
| Запуск | Чистая копия файлов Git, новый том БД, старт по README; down/up сохраняет историю |
| Автоматизация | GitHub Actions: verify, контейнерная проверка, отчёты и JAR; команды выполнены локально и на GitHub для 5afaace |

Выборы, требующие пояснения: JDBC позволяет явно выразить запросы к снимкам и иерархии; снимки делают отчёты воспроизводимыми; блокировка источников обеспечивает согласованность снимка; идентичность проблемы — правило, тип и ID объекта. Важность метрик отражает самую серьёзную текущую проблему; произвольные пороги не вводятся. Расписание и HTTP-запись не входят в реализованный объём; новый прогон запускается отдельной командой.

## Границы сдачи

Раздел «Тестовое задание» InternBTBack.pdf требует backend и REST API для страницы; реализация самой страницы в перечень не входит. InternBT.pdf описывает более широкий корпоративный проект. Storybook, существующие сервисы, корпоративные правила оформления и ИФТ не предоставлены; соответствие им и установку на ИФТ локальные проверки не подтверждают. Авторизация и корпоративная интеграция не реализованы. Windows отдельно не проверен. Удалённый CI для 5afaace завершён успешно: [успешный запуск GitHub Actions](https://github.com/wow-vulpes/InternSberBackend/actions/runs/41178861616).

При передаче решения достаточно ссылки на репозиторий с исходниками, README, миграциями, тестами и specs/. После отправки новых изменений результат CI нужно проверить для нового коммита; подтверждённый запуск относится к 5afaace. Локальные .env, кэши, target/ и пароли в состав сдачи не входят.

Развёрнутый [отчёт о соответствии](compliance-review.md) отделяет выполненный backend-объём от незакрытых корпоративных условий.

## Организационная часть сдачи по PDF

- Укажите ссылку на репозиторий в резюме, раздел «О себе» (InternBTBack.pdf, стр. 1).
- Подготовьте личные ответы о мотивации, роли в команде, количестве часов в неделю и периоде участия (стр. 3). Эти ответы пока не предоставлены.
- В PDF срок выполнения — 3 дня; ранее указан дедлайн до 8 ноября. Актуальный срок нужно подтвердить по договорённости с организатором.
- После ручного commit/push проверьте новый CI: опубликованный ранее успешный запуск не покрывает исправления JSON-контракта.
