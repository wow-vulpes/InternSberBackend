# Правила работы

- Общение и документация на русском; имена в коде на английском.
- Следовать согласованным этапам. Общий план не разрешает реализацию всех шагов.
- На каждом переходе представить результат и проверки, спросить: «Всё ли устраивает? Есть ли дополнения или исправления?», назвать следующий этап и дождаться явного разрешения.
- Для каждого шага: детальный дизайн → каркас → отдельные подэтапы реализации с тестами → проверка шага → подготовка коммита → отдельное разрешение на коммит.
- Внутри разрешённого этапа можно исправлять собственные ошибки и повторять необходимые проверки.
- Изменение согласованного объёма, архитектуры, зависимостей и публичных контрактов согласовывать до реализации. Рутинные настройки внутри утверждённого дизайна допустимы.
- Коммит не разрешает push или следующий этап. Не изменять Git-историю, не удалять пользовательские данные и не обходить ограничения инструментов.
- Не создавать фиктивные успешные ответы и классы для будущих функций.
- Не хранить секреты, локальные конфигурации и результаты сборки в репозитории.
- Сохранять исходные PDF без изменений.

## Технические соглашения

- Java 21, Spring Boot 3, один Maven-модуль в backend/.
- Планируемые пакеты: domain, application, persistence, api. Бизнес-правила независимы от HTTP и SQL.
- Constructor injection; явные зависимости; BigDecimal для весов и процентов.
- Зависимости фиксировать через Spring Boot BOM и явные версии внешних инструментов.
- Тестировать поведение и границы правил; для SQL и миграций использовать целевой PostgreSQL.
- Поддерживать specs/requirements.md и specs/design.md в соответствии с кодом. План и разрешения хранить в docs/.
- Не отмечать запланированное, непроверенное или не принятое пользователем как завершённое.

## Команды

Из backend/ при JAVA_HOME, указывающем на JDK 21:

```sh
./mvnw --version
./mvnw -B compile
./mvnw -B test
./mvnw -B verify
./mvnw spotless:check
./mvnw spotless:apply
./mvnw spring-boot:run
```

При validate автоматически проверяются JDK 21 и формат всех Java-исходников (Google Java Format, AOSP). Проверки выполняются и при compile/test/verify. Исправление форматирования — отдельная команда spotless:apply; обычная сборка файлы не переписывает.

KkdApplicationTest проверяет загрузку Spring-контекста без HTTP-сервера и БД. Этот тест не доказывает бизнес-корректность ККД.
