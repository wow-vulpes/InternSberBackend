# Требования к модулю ККД

Сервис проверяет качество целей сотрудников и ключевых результатов (КР), сохраняет историю проверок и отдаёт результаты через REST API.

Источники: InternBTBack.pdf — backend-тестовое; InternBT.pdf — описание корпоративного проекта. Этот документ и [design.md](design.md) составляют спецификацию, использованную при разработке с ИИ-ассистентом.

## Правила ККД

Выбраны четыре правила из списка ТЗ. Ниже также зафиксированы уточнения для случаев, в которых ТЗ не задаёт точного поведения.

| Код | Условие | Важность |
| --- | --- | --- |
| GOAL_NO_OWNER | У цели нет ответственного | critical |
| GOAL_NO_KR | У цели нет ни одного КР | critical |
| KR_WEIGHTS_SUM | Сумма весов КР цели не равна 100% | major |
| KR_STALE_PROGRESS | Факт КР не обновлялся более 45 дней | minor |

Неактивные цели и их КР исключаются из проверок и метрик. Пустой или пробельный ответственный считается отсутствующим. Цель без КР получает GOAL_NO_KR, без дополнительного нарушения суммы весов. При наличии КР сумма сравнивается с 100 точно, без округления; диапазон отдельного веса не проверяется выбранными правилами.

Возраст факта определяется относительно даты снимка: 45 дней допустимы, 46 — нарушение. Отсутствующая дата обновления считается нарушением, будущая дата — нет. Эти уточнения задают поведение там, где ТЗ не описывает граничный случай.

## Метрики и сравнение

Для сводки выбраны доля корректных целей и два счётчика из таблицы ниже. Область расчёта — выбранное подразделение и все его потомки. Каждая активная цель учитывается один раз; нарушение КР делает связанную цель некорректной.

| Метрика | Расчёт | Улучшение |
| --- | --- | --- |
| clean_goals_share | Активные цели без проблем / все активные цели × 100% | Рост |
| affected_goals_count | Уникальные активные цели хотя бы с одной проблемой | Снижение |
| issues_count | Число найденных проблем | Снижение |

Доля округляется до одного десятичного знака HALF_UP. Дельта — текущее показанное значение минус прошлое; для доли это процентные пункты. Trend: better, worse или unchanged; если значение для сравнения отсутствует — null. При отсутствии активных целей доля равна null, счётчики — 0.

Сравнение выполняется с последним успешно завершённым прогоном, дата снимка которого не позже текущей. Ссылка на него сохраняется при создании прогона и затем не меняется. Иерархия подразделений берётся отдельно из каждого снимка. Если подразделения в прошлом снимке не было, прошлые счётчики равны 0, доля — null. Если нет самого прошлого прогона, compared_to, прошлые значения, дельты и тренды равны null.

Идентичность проблемы — правило, тип и ID объекта. Новые проблемы отсутствовали в прошлой области; сохраняющиеся есть в обеих; исправленные отсутствуют в текущей. Перенос, удаление или деактивация цели также могут убрать проблему из области — категория resolved не обязательно означает ручное исправление данных.

Разбивка по важности содержит current/previous/delta для critical, major и minor, включая нули. Без прошлого прогона previous/delta равны null. Дополнительная severity каждой метрики отражает самую серьёзную текущую проблему области; без проблем — null. Произвольные пороги качества не вводятся.

## История и запуск прогонов

Каждый обычный запуск создаёт новый прогон, в том числе при повторе даты. Завершённые и неуспешные прогоны, их снимки и проблемы защищены от изменения обычными операциями записи. RUNNING и FAILED не выдаются как готовые результаты; их число проблем — null. Сводка и список проблем доступны только для COMPLETED.

Незавершённые результаты не публикуются. При ошибке расчёта частичные данные откатываются, прогон получает FAILED. При инфраструктурном сбое до создания строки или при фиксации транзакции сохранение FAILED не гарантируется.

Демо создаёт два прогона атомарно. Повторный запуск использует готовую демопару и сохраняет последующие изменения источников и дополнительные прогоны. Заполненная БД без демопары отклоняется без изменений. Локальный Java-старт создаёт демо только по явному флагу; Compose включает его по умолчанию. Новый прогон запускается отдельной командой, дата по умолчанию — сегодня UTC.

## Результаты проверки

Полный Maven verify: 259 сценариев без ошибок и пропусков, исполняемый JAR собран. На PostgreSQL 17.11 проверены накат, откат заполненной истории и повторный накат со сравнением структуры. На Linux проверены запуск без .env с новой БД, сохранение истории после down/up, отсутствие дублей демо и восстановление после отказа БД. Для проверок использованы отдельные временные БД.

Команды воспроизведения и контрольные значения демо находятся в [README](../README.md). Результат CI относится к конкретному коммиту; после изменений требуется успешный workflow для новой версии.

## Границы реализации

Раздел «Тестовое задание» InternBTBack.pdf требует самостоятельный backend и API для страницы ККД. Создание самой страницы в этот перечень не входит. InternBT.pdf описывает более широкий корпоративный проект: Storybook, существующие сервисы и данные, правила команды и ИФТ. Эти материалы и доступ не предоставлены; корпоративная интеграция и стендовая приёмка не подтверждены.

Авторизация и автоматический еженедельный запуск не реализованы. В backend-тестовом нет отдельного обязательного пункта создания планировщика или хранимой процедуры запуска ККД. Windows отдельно не проверен. Организационные условия сдачи и мотивация приведены в README.
